What’s in the demo

The whole filing lifecycle, as an API.

Everything below runs today in test mode. We mark what is still in progress or on the roadmap, so you know what you can build against.

Live in demo

Pre-flight validation

Field-level errors with a JSON path, a code and a fix. Blockers stop a filing, warnings do not. Add ?mode=validate for a dry run that stores nothing.

Live in demo

TIN checks

Format rules for SSN, EIN, ITIN and ATIN plus known-invalid patterns. A full TIN is never echoed back. Format only: IRS TIN matching is not part of the demo.

Live in demo

Bulk readiness check

Send the IRS template CSV or JSON rows for any of the 37 forms and get a grouped report with row numbers and fixes. POST /v1/forms/{id}/validate, nothing stored.

Live in demo

Filing lifecycle

Create, submit, read acknowledgements. An explicit state machine (ready, submitted, accepted, rejected, failed) and a queryable status on every filing.

Live in demo

Corrections and replacements

Fix a rejected filing with POST /v1/filings/{id}/corrections. The new filing links to the original, which is marked corrected.

Live in demo

FIRE file import

Convert an IRS Pub 1220 file into filings. Checks payee counts and control totals, reports what it cannot map instead of guessing, and re-uploading the same file creates no duplicates.

Live in demo

Idempotency

Send an Idempotency-Key and retries return the first response. The same key with a different body is a clear 409.

Live in demo

Signed webhooks

Nine events, an HMAC-SHA256 signature with a timestamp, and up to six delivery attempts with backoff. Your product never has to poll.

Live in demo

Test mode with a simulator

Magic TINs and payer names reproduce acceptance, rejection, slow acknowledgements and IRS outages. No IRS, no risk, no real data.

Live in demo

Audit log and usage

Every filing action is recorded and metered per month and mode. GET /v1/audit, GET /v1/usage.

Live in demo

Encryption and rate limits

AES-256-GCM at rest for filing data, generated XML and webhook secrets. Per-account limits with RateLimit-* headers.

Live in demo

Edge-deployed, runs locally too

Cloudflare Workers with Postgres. The same code runs on your laptop with the irisfile CLI: dev, validate, sample, forms, template, check, fire.

Live in demo

OpenAPI and clear errors

An OpenAPI 3.1 spec, application/problem+json errors with stable codes, and copy-paste examples in the docs.

In progress

IRIS A2A transmitter

Implements IRS Pub 5718: OAuth2 JWT-bearer, multipart intake, status polling. So far it has only run against our own protocol sandbox, not the IRS.

Roadmap

Real IRS filing

Needs an IRIS TCC, an API client certificate, the IRS schema package and a pass on the IRS test system. Until then the XML is provisional and live mode is off.

Use cases

Built for software that generates tax data.

Pick your platform. Each scenario shows what you send, what comes back and what works in the demo today.

Year-end 1099-NEC for every contractor you paid.

You pay thousands of contractors through your platform. In January you need a clean 1099-NEC for each one, and a plan for the ones the IRS bounces.

  1. Map payouts to recipients[].nonemployee_compensation.
  2. Dry-run the batch to catch bad TINs and states in December, not January.
  3. Create and submit with an Idempotency-Key per payer.
  4. Listen for filing.rejected and send a replacement with one call.

Seller and creator payouts, reported at scale.

A marketplace pays out to sellers and creators. Some reach payment-network thresholds, others are plain service payments. You need to sort them, check the data and file.

  1. Download the IRS CSV template for the form you need.
  2. Run the bulk readiness check on your export and get row-level problems.
  3. File the 1099-NEC and 1099-MISC population through the API.

Information-return filing inside your own product.

You run payroll, HR or accounting software. Your customers expect 1099s to just work, and your engineers do not want to learn IRS transmission.

  1. Create a filing per customer (payer) from the data you already hold.
  2. Show validation issues in your UI with the field path and the suggested fix.
  3. Register a webhook and update status without polling.
  4. Keep the audit trail and usage per account.

Interest and dividends for every account holder.

A bank, credit union or investment app reports interest and dividends. Foreign tax paid, bond CUSIPs and qualified-dividend splits all have to line up.

  1. Send box amounts in recipients[].amounts and text boxes in details.
  2. Rules catch a portion larger than its total (for example qualified dividends over ordinary dividends).
  3. Submit, track and correct like any other filing.

Rents and vendor payments, every year, no spreadsheets.

Property managers report rents paid to owners and fees paid to vendors. The data is recurring, so the filing should be too.

  1. Rents go in 1099-MISC amounts.rents, vendor services in 1099-NEC.
  2. Validate the batch whenever data changes, then submit once it is clean.
  3. Replace a filing when a payee changes details.

Keep your FIRE files. Move to IRIS.

You already produce FIRE flat files. Rather than rebuild the pipeline, point it at the importer and keep going while the IRS moves from FIRE to IRIS.

  1. Upload the Pub 1220 file. Nothing is stored on a dry run.
  2. Review the result: payee counts, control totals, what was skipped and why.
  3. Re-upload with ?create=true to create the filings. Sending the same file again creates nothing twice.
1099-NEC1099-MISC1099-INT1099-DIV

In the demo today: import for the four forms above. Other forms and G/C corrections are reported as skipped, not guessed.

FIRE is changing. Your infrastructure has to change with it.
